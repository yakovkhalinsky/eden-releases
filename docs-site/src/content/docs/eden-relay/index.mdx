## What it is

`eden-relay` is a lightweight, self-hosted sync relay for [eden-memory](/eden-memory/). It is a single static Go binary with no MCP or memory subcommands — its only job is to let eden-memory devices discover each other and exchange encrypted delta envelopes across separate networks.

The relay never sees memory contents. It only routes opaque envelopes between paired devices that share the same account root key.

## Quick start

```bash
# On the relay host
curl -fsSL https://0d3sa.com/eden-memory/install.sh | sh -s eden-relay
eden-relay --db /var/lib/eden-relay/relay.db --addr 127.0.0.1:8787

# Check it
curl http://127.0.0.1:8787/health
```

The relay binds to loopback by default. To accept connections from other devices, pass `--allow-remote-bind` (or set `EDEN_RELAY_ALLOW_REMOTE_BIND=1`) and a non-loopback `--addr`. See [CLI, env vars, and endpoints](/eden-relay/reference/) for every flag and endpoint.

## When to use it

Use `eden-relay` when you want continuous sync between eden-memory devices on different networks — for example, a laptop and a desktop, or a CI runner and a workstation.

For one-shot sync between two databases on the same machine, use `eden-memory sync` directly. See [Sync two databases locally](/eden-memory/tutorials/sync-local-databases/).

## How it fits together

1. Devices pair via PAKE and share an account root key.
2. Each device registers with the relay using the same `account-id`.
3. Devices exchange signed delta logs through the relay.
4. Conflicts are resolved locally with logical clocks.

Devices register with the relay through `eden-memory pair create-invitation` / `pair accept-invitation`, or through the `eden_relay_register` MCP tool. The relay itself never handles pairing passwords or passphrases.
