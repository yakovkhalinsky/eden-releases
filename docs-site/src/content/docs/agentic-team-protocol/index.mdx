## What it is

The **Agentic Team Protocol (ATP)** is a lightweight operating model for running small, structured agent teams inside Claude Code. It stores a durable trail of every decision in [eden-memory](/eden-memory/) and keeps the **Verifier gate mandatory** before any goal is closed.

By default, `/team` now runs **Lite mode**: a 4-stage path that handles everyday implementation tasks without the ceremony of the full protocol. For research-heavy, live-system, risky, or heavily-audited work, use `/team-full` to run the complete 6-role, 7-stage lifecycle.

## Lite mode vs full protocol

| | Lite mode (`/team`) | Full protocol (`/team-full`) |
|---|---|---|
| Stages | 4 (goal → plan → act → check) | 7 (goal → route → research → act → verify → archive → close) |
| Roles used | dispatcher, builder, verifier, archivist | dispatcher, researcher, builder, runtime, verifier, archivist |
| Research phase | Folded into dispatcher planning | Separate `researcher` role |
| Live-system work | Builder handles low-risk cases; escalate otherwise | Dedicated `runtime` role with charter gating |
| Charter ratification | Optional | Required for charter-heavy projects |
| Best for | Everyday implementation and docs | Complex, risky, or audited goals |

## Default roles

| Role | Responsibility | Active in |
|------|----------------|-----------|
| Dispatcher | Decides what gets built, records the goal, and plans the approach. | Lite + Full |
| Researcher | Investigates options and writes decision-ready reports. | Full only |
| Builder | Implements the chosen approach. | Lite + Full |
| Runtime | Executes operational actions — gated by default. | Full only (Lite: builder handles low-risk ops) |
| Verifier | Reviews correctness, safety, and charter compliance. | Lite + Full |
| Archivist | Records the goal lifecycle and manages memory hygiene. | Lite + Full |

Runtime is not active unless your project charter explicitly authorises it.

## What you need

- [eden-memory](/eden-memory/getting-started/) installed and on your PATH.
- Claude Code CLI (the protocol is implemented as global agents and slash commands).
- Optionally, the [eden-team](/eden-team/) binary for headless, non-interactive goals.

## Quick install

Install `eden-memory` first, then install the ATP global primitives:

```bash
curl -fsSL https://0d3sa.com/eden-memory/install.sh | sh
curl -fsSL https://0d3sa.com/agentic-team-protocol/install.sh | sh
```

In each project where you will use ATP, wire the Eden-memory MCP server before restarting Claude Code:

```bash
cd ~/my-project
eden-memory setup claude
```

Then restart Claude Code completely (`/exit`, then reopen). The agents and commands will be available in every workspace.

See the [getting started](/agentic-team-protocol/getting-started/) guide for the manual install path and project-local charter setup. Read the [charter anatomy](/agentic-team-protocol/charter-anatomy/), [lifecycle](/agentic-team-protocol/lifecycle/), and [agent prompts](/agentic-team-protocol/reference/agent-prompts/) for the full protocol reference.

## How it uses eden-memory

The protocol does not replace eden-memory; it stores every milestone in it.

- `/team-charter` reads `.claude/agentic-team-charter.md`, computes a SHA-256 version hash, and writes a `charter_ratification` record to eden-memory.
- Every role uses the eden-memory MCP tools (`eden_remember`, `eden_recall`, `eden_search`, `eden_search_semantic`, `eden_edit`, `eden_forget`, etc.) to read prior context and store new records.
- Required record kinds link the lifecycle together:

  | Kind | Stage | Owner | Mode | Purpose |
  |------|-------|-------|------|---------|
  | `goal_record` | goal_receipt | dispatcher | lite + full | Initial request and constraints. |
  | `plan_record` | plan | dispatcher | lite only | Combined routing + context + success criteria. |
  | `dispatch_instruction` | routing_and_assignment | dispatcher | full only | Who does what, by when. |
  | `context_summary` | context_gathering | researcher | full only | Findings and options considered. |
  | `action_record` | action | builder / runtime | lite + full | What was done and how to roll back. |
  | `verdict` | verification | verifier | lite + full | Green, red, or blocked assessment. |
  | `escalation_record` | escalation | dispatcher | lite + full | Authority or guardrail request. |
  | `charter_ratification` | charter_ratification | archivist | full mostly | Project charter approval. |
  | `archival_record` | recording_and_archival | archivist | lite + full | Final outcome and links. |

Each record should include metadata fields: `goal_id`, `stage`, `owner_role`, `input_record_ids`, `output_record_ids`, and `recalled_memory_ids`.

When recalling memory, only treat results with a score **≥ 0.45** as relevant, and record the IDs of memories that shaped the record in `recalled_memory_ids`.

## Memory-first rules

Every ATP role reads and writes eden-memory. Follow these rules in every task:

1. **Recall first** — Immediately after receiving a task, call `mcp__eden-memory__eden_recall` with the task summary to check for relevant conventions and prior context.
2. **Recall before decisions** — Before any decision that touches user preferences, coding style, security, or tooling, call `mcp__eden-memory__eden_recall` first.
3. **Remember after corrections and settled conventions** — After a correction, working solution, or agreed convention is established, call `mcp__eden-memory__eden_remember` to store it.
4. **Batch durable takeaways** — At the end of every task, batch **3–5 durable takeaways** into `mcp__eden-memory__eden_remember` calls.
5. **Never remember sensitive or unvalidated content** — Do not remember secrets, tokens, raw command output, ephemeral reasoning, or unvalidated guesses.
6. **Use fallbacks if MCP is unavailable** — If `eden_recall` / `eden_remember` tools are unavailable, use the `/eden-remember`, `/eden-recall`, and `/eden-search` fallback slash commands instead.

Example recall and remember shapes:

```json
{
  "agent_id": "claude-code-cli",
  "user_id": "yakov",
  "content": "Prefer table-driven tests with testify/require.",
  "ttl_ms": null
}
```

```json
{
  "agent_id": "claude-code-cli",
  "user_id": "yakov",
  "query": "testing style"
}
```
